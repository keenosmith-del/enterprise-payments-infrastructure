# M01 hosted verification evidence

The following is an intermediate observed run, not a claim about a later commit. On 26 November 2026, [M01 foundation run 45852952727](https://github.com/keenosmith-del/enterprise-payments-infrastructure/actions/runs/45852952727) succeeded on commit `0992b3682bdee1fbccd1078422e5de569bcffedd` on GitHub-hosted Linux x86-64. The independent [M00 run 45852953151](https://github.com/keenosmith-del/enterprise-payments-infrastructure/actions/runs/45852953151) succeeded on the same commit.

The M01 run reported 16 backend unit tests passed, four migration smoke tests passed, one database-boundary test passed covering four applications, four real Keycloak token tests passed, and one restricted RabbitMQ transport test passed. The Compose job reported five authenticated HTTP authorization tests passed, four Playwright browser tests passed, and one additional RabbitMQ permission test passed. It repeated the five HTTP authorization tests after a PostgreSQL restart. Frontend type checking and all four production builds passed. npm audit reported zero vulnerabilities and pip-audit reported no known vulnerabilities for the locked application dependencies. The precise expected values and negative assertions are in the test sources; counts above describe test cases, not the number of individual security assertions.

Earlier run 45848451988 exposed an asynchronous Pika channel-close assertion error even though the broker logged the expected access denial. Publisher confirms corrected the observation. Runs 45850742335, 45850961378 and 45851166471 failed because Compose waited on an explicitly selected successful one-shot container as if it were a daemon. A subsequent correction runs that setup separately. Later runs 45851940577 and 45852279761 failed at the integration-service command capture. The corrected non-interactive invocation passed in run 45852952727. The first Keycloak run failed on an incomplete synthetic account profile; the next exposed a missing managed tenant attribute. The profile and administrator-controlled claim mapping were corrected before the successful run above.

The execution host was macOS ARM64 with no available local Docker daemon. These hosted results are not native ARM64 container verification. Runtime tests use synthetic data, loopback ports and disposable credentials. Later final-commit verification must be checked separately.
