# M01 verification record

Hosted workflows preserve the separate M00 verification and an M01 foundation workflow. The M01 jobs install hashed Python dependencies and the npm lock, run unit, lint and type checks, build all frontends, test disposable PostgreSQL migration and database identity boundaries, exercise a real RabbitMQ broker and real Keycloak tokens, and run a Compose stack with browser and authorization tests. The stack job exercises restart and optional infrastructure. The dependency-security job audits the Python lock and rejects tracked private-key material; the frontend job runs npm audit.

The local execution host was macOS ARM64. Its Docker daemon was unavailable, so container checks are hosted Linux x86-64 checks. Local Python unit tests and frontend type checks and builds were run; no native ARM64 container run is claimed. The initial dependency audit found vulnerable Starlette, JWT, telemetry and pytest versions. Updated pins passed the local unit and type checks and the subsequent Python audit reported no known findings. The original RabbitMQ test initially failed because asynchronous channel closure was not observed by the assertion; publisher confirms made the denial synchronous. A Compose wait command initially treated a successful one-shot provisioning container as a failure and was corrected.

Run URLs, exact results and final SHA belong in the [completion report](M01_COMPLETION_REPORT.md) after the final workflow completes. Historical intermediate evidence is retained under `evidence/m01/`. A green workflow verifies its implemented checks and must not be interpreted as production certification.
